# Machine registry: vocabulary and public status

This directory holds the machine-readable claim registry:

- `claims/*.json`: ClaimContracts (schema:
  [`schemas/research-claim-contract.v1.schema.json`](../schemas/research-claim-contract.v1.schema.json)),
  each content-addressed by `content_hash`.
- `assumptions.v1.json`, `campaigns.v1.json` and `snapshots/current.lock.json`:
  generated by [`tools/generate_assumptions.py`](../tools/generate_assumptions.py)
  from the claims, the EvidenceBundles in `evidence/v1/examples/` and the
  campaign manifests in `campaigns/v1/`. Do not edit them by hand; run the
  generator (`--check` verifies them).
- `ontology/`: hash-pinned ontology snapshots (see
  [`ontology/README.md`](ontology/README.md)).

A status change in `assumptions.v1.json` (or in the locked ontology) must arrive
with an EvidenceBundle hash that did not exist before
([`tools/check_status_evidence.py`](../tools/check_status_evidence.py), run on
pull requests). That check does not read `claims/*.json` directly; edits to a
ClaimContract's statement or classification are reviewed like any other change.

The registry's words are machine states. They are not the words we use in public.
Public result statuses are the ones in the
[conjecture ledger](../docs/conjectures/ledger.md#status-legend): Supported, Open,
Failed, Abstained, Refuted by us, Self-corrected, Withdrawn. "Lean-checked
arithmetic" is a badge, never a status. When the two disagree, the ledger is the
public statement, and the registry entry should be brought into line through the
procedure above.

## ClaimContract `classification.outcome`

| Registry value | Public status | Notes |
|---|---|---|
| `pending` | Open | Registered, not yet tested. |
| `supported` | Supported | Only within the contract's statement and `excluded_scope`; carry its qualifiers wherever the number appears. |
| `partially_supported` | Open | Say which part held and which did not. |
| `inconclusive` | Abstained, or Open | Abstained when the registered rule declined to issue a verdict (for example, no available model had the physics the test needed); Open otherwise. |
| `contradicted` | Failed, or Refuted by us | Failed when a gate written in advance was not met; Refuted by us when our own later test overturned an earlier claim. |
| `withdrawn` | Withdrawn | We stopped claiming it or relabelled it as not evidence. |

## ClaimContract `classification.assurance` and generated `status` / `disposition`

These describe the strength of the evidence attached to a contract and drive the
runtime gate. They never upgrade a public status on their own.

| Registry value | Meaning in the registry | Public reading |
|---|---|---|
| `unsupported` | No EvidenceBundle supports the premise. | Open (or Abstained, per the outcome above). |
| `provisional` | Best attached evidence is exploratory. | Open. |
| `eligible` | Best attached evidence is descriptive. | Open. |
| `active` | Attached evidence is confirmatory for the stated scope. | Supported only for that scope, with its qualifiers. It is not a product claim and not a "public correction scope" by itself. |
| `withdrawn` (with disposition `refuted`) | A negative EvidenceBundle is attached. | Failed, Refuted by us or Withdrawn, as the ledger records. |

## EvidenceBundle `epistemic_status`

| Registry value | Public reading |
|---|---|
| `confirmatory` | Evidence from a test registered in advance. |
| `descriptive`, `exploratory` | Context, not a test: at most Open. |
| `negative` | The registered test failed or contradicted the premise. |
| `unsupported` | Recorded, but supports nothing (for example a baseline or a smoke run). |

## Measurement rows `acceptance_test.outcome`

`pass` and `fail` map to a gate that was met or not met; `abstained` maps to
Abstained.
