# Included-subscription coding broker installation

This source is an integration overlay for the existing `lupine-research-team-v02` Worker. It is not a second provider account, a hosted entitlement claim, or an amendment to historical research task permits.

Copy `research-entrypoint.ts` to the research service's `cloudflare/coding-model-broker.ts`, copy `worker-fetch.ts` to `cloudflare/coding-model-worker-fetch.ts`, and copy `src/coding/model-broker-core.ts` beside them as `cloudflare/model-broker-core.ts`. Record all three source hashes. The imports then resolve against the retained MiniMax runtime and account DO. Do not edit those runtime files or native/Claude bundles.

Run `node integrations/research-coding-broker/install.mjs <research-package> <new-receipt.json>` against the exact baseline. It adds a new main wrapper that re-exports the byte-identical public Worker and the new broker. Add a SQLite DO binding `CODING_MODEL_BROKER` with class `CodingModelBroker`; the pinned Wrangler exports configuration declares its SQLite storage. Preserve every existing binding and runtime identity. Enable `nodejs_compat` explicitly because the reused validator uses `Buffer`. Build and typecheck this installed composition; the overlay's relative imports intentionally resolve only in the research service.

The coding runner receives a service binding to this exact existing service and `CodingModelBrokerEntrypoint`, with deployment-controlled props `consumerService: "lupine-coding-runner-v01"` and `protocol: "lupine.coding-model-broker.v1"`. The public Worker router must not expose this entrypoint. Neither the guest nor its task capability may call the account DO, observe/configure proof, or choose credentials/policy/model/endpoint.

Existing `MINIMAX_SUBSCRIPTION_KEY`, `MINIMAX_POLICY_SHA256`, `MINIMAX_CREDENTIAL_GENERATION_SHA256`, `MINIMAX_ACCOUNT`, and private `MEMORY` remain in their current service. The fixed shared account is `lupine-team-minimax`. At open, the core durably binds server policy/generation to the task permit; runtime rechecks the actual account identities. No keys are copied to the runner, task manifest, image, or guest.

Binding-only POST interfaces are `/ready {model}`, `/open {permit}`, `/invoke {attemptId,turn}`, and `/close` or `/status {attemptId,inputSha256}`. Ready refreshes authenticated quota only when the existing credits-OFF proof is valid; it cannot renew that proof or run inference. Guest transport uses the runner's separately issued task capability, not this service binding. The runner closes the permit before finalization and preserves `pendingUnknown`; close prevents future calls but cannot undo a committed provider dispatch.

The durable permit consumes up to sixteen ordinals shared by all sessions, limits output to 4096 tokens and request bodies to 256 KiB, and expires by the original runner deadline. Each turn has a 120-second enclosing ceiling shortened by permit expiry. Session system/tools are fixed; exact sanitized message prefixes are joined to the private, hash-verified continuation before restoring provider reasoning. Completed results require existing account settlement plus private R2 readback. Duplicate ordinals return metadata only. Unknown/lost acknowledgements never cause a new inference, even after a new DO instance.

The Worker-local fetch shim permits only exact MiniMax quota/messages endpoints, removes Bun's `timeout` option, uses manual redirects, rejects every 3xx, and combines the enclosing signal with the runtime signal. No fallback provider exists. Private archives include reasoning and prompts and must remain behind existing operator authorization. Status and guest output contain no raw reasoning.

Local SQLite fault tests establish application logic only. Installed workerd compatibility, exact service props, provider proof freshness, real hosted inference, shared account reconciliation, guest continuation, and cleanup each require separate receipts. Do not treat scripted DSH qualification or this source overlay as evidence of live subscription access.
